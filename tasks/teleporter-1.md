# Задача teleporter-1: блок «Телепорт» 2×4×3 с проходом внутрь и твёрдыми стенками по форме

Ветка: `ai/teleporter-1`. Перед работой прочитай `CLAUDE.md`, `DEVELOPER.md`, `CONTENT.md` (раздел 2: `size`, `shape`,
`animation`), отчёт `tasks/workbench-1-report.md` и код `modules/blocks/` (`BlocksModule`, `Multi`) и
`client/core/.../block/` (`PoolBlocks`, `CustomBlocks`, `Remap`). Отчёт — `tasks/teleporter-1-report.md`,
вопросы — `tasks/teleporter-1-questions.md`.

## Что есть

Многоклеточные свои блоки уже работают (workbench-1, мод 0.84+): `size`, `shape` (одна коробка на клетку, одинаковая
для всех клеток), `animation`. Телепорту этого мало: внутри должна быть **пустота, в которую игрок заходит**, а стенки
колбы — **твёрдые по своей форме** (восьмигранник), разные в разных клетках. Нужен новый общий механизм:
**коллизия по частям из файла** — у каждой части блока свой набор коробок.

## Размеры (не менять)

* Габарит **2 × 3,5 × 3 блока** → `size: [2, 4, 3]` (X × Y × Z). Лицо (проход) — **север (−Z)** при повороте 0, как у
  верстака: должно смотреть на игрока, который ставит.
* Внутри: диаметр по стеклу 1,75 блока, высота от пола до потолка **2,25 блока** (пол на 4 px = ¼ блока над землёй,
  потолок на 40 px), запас над головой 7,2 px. Проход спереди: самое узкое место — между косяками, ≈ 1,1 блока (игрок 0,6). Пол — ¼ блока,
  игрок поднимается сам (как на плиту), ступенька не нужна.
* Сзади машинный блок до высоты 3,5 блока, сверху крышка (на 2,5…3 блока) — над головой, не мешает.

## Сделать

### 1. Модуль `blocks` — поле `collision`
```yaml
teleporter:
  name: "Телепорт"
  model: teleporter.bbmodel
  animation: idle
  size: [2, 4, 3]
  collision: teleporter_collision.json   # новое: коробки по частям; при наличии — вместо shape
  rotatable: true
  sounds: { type: metal }
```
* Читать файл из `module/blocks/assets/`, проверять: каждая коробка внутри 0…16 по X/Z и 0…32 по Y, `x1<x2` и т. д.;
  ключи частей — в пределах `size`. Битый файл → блок не регистрировать, ошибка в лог (не падать).
* Часть без записи в файле — **без коллизии** (проходимая, как воздух). Это нужно для внутренних клеток.
* Моду отдавать коробки в `blocks.json` по каждой части × повороту (повёрнутые на сервере или поворот на клиенте —
  на твой выбор, но один раз и одинаково с тем, как `Multi` поворачивает расположение частей). Поворот коробок —
  вокруг центра клетки (8, 8) на 90°·r, с перестановкой частей как у `Multi`.
* Носители: проходимые части (без коробок) — из запаса `passable`, остальные — `transparent`. 24 части × 4 поворота:
  проверь остаток запасов и напиши в лог/отчёт, сколько ушло. `states.yml` только дополнять.
* Описать поле `collision` в `CONTENT.md` (таблица раздела 2).

### 2. Ядро мода — форма блока из нескольких коробок (поднять `version`)
* `PoolBlocks`: форма (коллизия и рамка выделения) части = объединение её коробок (`Shapes.or` из `Block.box`),
  кэш по (блок, часть, поворот), без созданий на кадр. Пустой список — пустая форма. Старое поле `shape` продолжает
  работать как одна коробка.
* Рамка выделения может совпадать с коллизией (ничего хитрого не надо).
* Стекло: проверь, что прозрачные пиксели атласа (alpha 0) действительно не рисуются и в меше чанка (cutout), и в
  кадровом рисовании анимированного блока. Если где-то стекло становится непрозрачным — чинить в ядре, модель не менять.

### 3. Поведение «игрок внутри» (только событие, без телепортации)
* Сервер раз в 5 тиков проверяет игроков рядом с поставленными телепортами: ноги игрока внутри колбы (круг радиусом
  12 px вокруг центра колбы на уровне пола главной клетки +4 px) → событие `HoBlockInsideEvent(player, blockId, pos)`
  при входе и выходе, в `api`/`HoBlocks` по образцу `HoBlockUseEvent`. Общий механизм: поле `inside: [x1,y1,z1,x2,y2,z2]`
  (px, в системе модели) в описании блока; у телепорта — цилиндр внутри стекла можно задать коробкой.
* **Куда и как телепортировать — не придумывать.** Запиши вопрос в questions (связка пар телепортов? команда
  `/hotp link`? задержка, эффект, звук?). Для проверки — отладочное сообщение игроку при входе/выходе (только OP).

## Тесты (JUnit 5)
* разбор `teleporter_collision.json`: 24 части, все коробки в пределах, битый файл не регистрирует блок;
* поворот коробок на 0/90/180/270 + перестановка частей: для каждого поворота сумма объёмов та же, коробки остаются в
  своих клетках, проход оказывается со стороны «лица» (для 4 поворотов — с 4 разных сторон);
* «игрок проходит»: прогнать хитбокс 0,6×1,8 блока от точки перед проходом до центра колбы с подъёмом на шаг ≤ 0,6
  блока (как `player_fits` в генераторе) по коробкам после поворота — проход свободен на всех 4 поворотах, сквозь
  стекло сбоку и сзади — нет;
* мод: объединение коробок даёт правильные `AABB` формы.

## Как проверить в игре (в отчёт)
`/hoblock give teleporter` → поставить на 4 стороны: проход смотрит на игрока; F3 — `hoka_odyssey:teleporter`.
Зайти внутрь, встать в центр, попрыгать (головой в крышку не застревать), выйти. Пройти вдоль колбы снаружи — стекло
и стойки твёрдые, сквозь стекло не пройти и не просунуться, сзади машинный блок твёрдый. Стекло прозрачное (видно
игрока внутри), кольца в полу и потолке крутятся. Рамка выделения по форме. Отладочное сообщение при входе/выходе.
Сломать любую часть — весь телепорт пропадает, 1 предмет. Перезайти — на месте.
