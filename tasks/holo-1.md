# Задача holo-1: голограммы на моде (кубоидный космический стиль) + очень функциональный редактор

Новые модули: сервер `modules/holo`, клиент `client/modules/holo`. Голограммы рисует **мод** (не ванильные
TextDisplay/ArmorStand): панель в стиле космоса и кубоидов, в неё выводятся текст, предметы, картинки, шкалы, кнопки
с действиями. Главное требование пользователя — **очень функциональный редактор** прямо в игре.
Чужие модули tearsmilk (`items, gravity, gravzones, oxygen, starmap, guns`) не трогать. Делай по порядку 1→5,
**коммить после каждого пункта и сразу обновляй `tasks/holo-1-report.md`** (бюджет ограничен — если работа
оборвётся, сделанное и отчёт должны остаться).

## Стиль (обязательно)
Космос + кубоиды (как HUD кораблей `client/modules/vessels/.../hud/*` и границы станций `client/modules/stations`):
- панель — тёмная полупрозрачная (`0x05080F`), рамка из **маленьких светящихся кубиков-вокселей** по краю (объёмные,
  1/16 блока, светлые `0xD9E2EE` / голубые `0x8FD8FF`, акцент янтарный `0xFFC46B`), уголки — кубики крупнее;
- лёгкие «сканлинии»/мерцание, мягкое свечение (смесь «свечение», как у плёнки станций), без ванильных текстур;
- появление: кубики рамки «собираются» из точек за ~0.4 с; при удалении — рассыпаются;
- лёгкое парение по высоте (вкл/выкл), режимы поворота: фиксированный / к игроку по Y (billboard) / полностью к игроку;
- темы оформления (палитры) в конфиге: `space` (по умолчанию), `amber` (предупреждение), `danger`, `green`.

## 1. Модель данных и сервер (`modules/holo`)
- Голограмма: id, карта, позиция, поворот (yaw/pitch), режим поворота, масштаб, тема, ширина панели (авто/фикс),
  отступы, фон вкл/выкл и прозрачность, рамка вкл/выкл, дальность видимости, условие видимости (все / OP / право
  `holo.view.<id>` — права через ядро, если есть), список **строк**.
- Строка — один из элементов (можно несколько в строку — «ряд»):
  - **text** — MiniMessage (цвета, жирный, градиенты), размер шрифта (0.5–4), выравнивание; плейсхолдеры:
    `{player}`, `{online}`, `{time}`, `{map}`, `{x} {y} {z}` игрока, и **плейсхолдеры от других модулей** через
    сервис `HoloApi.placeholder("имя", (player) -> строка)` — значение считается на сервере для каждого игрока, обновление
    с периодом (у плейсхолдера своя частота), рассылка только изменившегося;
  - **item** — предмет (в том числе свои из `hoitems` по id), вращение вкл/выкл, размер; подсказка при наведении;
  - **image** — PNG из файлов модуля (`ClientModsApi.putFile`), размер в блоках;
  - **bar** — шкала (значение из плейсхолдера 0..1 или числа), цвет;
  - **button** — подпись + **действия** по ЛКМ/ПКМ: команда от игрока, команда от консоли (только если голограмму
    создал OP), сообщение, звук, телепорт, открыть окно `houi`, переключить «страницу» голограммы; задержка нажатия;
    условие (OP/право);
  - **separator**, **spacer**.
- **Страницы**: голограмма может иметь несколько страниц (кнопки «‹ ›» или действие `page`), страница — своя у каждого
  игрока.
- Клик по любой голограмме/строке тоже может иметь действия (не только кнопки).
- Хранение — `module/holo/holograms.json`, атомарно, битый файл не перезаписывать. Изменения — сразу всем, без reload.
- Сервис `HoloApi` для других модулей: создать/обновить/удалить голограмму кодом (временные — без записи в файл),
  плейсхолдеры, событие нажатия. Пример использования положи в отчёт.
- Команды (OP, `/hoholo`): `create <id>` (перед игроком), `remove`, `list`, `tp`, `movehere`, `copy <id> <новый>`,
  `edit [id]` (открыть редактор), `reload`, `addline <id> <текст>` и т.п. — минимум, главное — редактор.
- Сервер проверяет нажатия: расстояние, видимость, задержка, права; консольные команды — только у голограмм OP.

## 2. Отрисовка (`client/modules/holo`)
- Через `ClientContext.onWorld` (как `stations`), свои пайплайны (смотри `StationsClientModule` — там уже есть
  POSITION_COLOR со «свечением» и текстурный с повтором), текст — шрифтом игры в мире (как таблички/ники: `Font.drawInBatch`
  с матрицей), предметы — рендером предметов игры в мире, картинки — `ctx.texture(path)`.
- Производительность: рисовать только ближние (дальность), отсечение по кадру, кэш раскладки (не пересчитывать
  строки каждый кадр — только при изменении данных), большие координаты — относительно камеры. Десятки голограмм не
  должны заметно ронять FPS (у нас был опыт: плёнка станций линиями роняла FPS вдвое — считай квады, текстуры вместо
  тысяч линий).
- Наведение: луч от глаз к панелям; наведённая кнопка подсвечивается (кубики рамки кнопки ярче, лёгкий сдвиг),
  курсор-точка; клик ЛКМ/ПКМ по кнопке забирается модом (`ctx.onClick` → true) и уходит серверу.

## 3. Редактор (главное) — экран мода
Открывается `/hoholo edit [id]` или клавишей (по умолчанию `J`, только OP — сервер говорит моду, что можно) при
взгляде на голограмму. Окно в том же стиле (тёмная панель, кубоидные рамки). Должно уметь:
- **Список голограмм** (поиск, фильтр по карте, расстояние, телепорт, создать, копировать, удалить с подтверждением).
- **Свойства** выбранной: позиция (числа + кнопки сдвига ±0.1/±1, «сюда», «к блоку под прицелом»), поворот, режим
  поворота, масштаб, тема, ширина, фон, рамка, парение, дальность, видимость, страницы (добавить/удалить/порядок).
- **Строки**: добавить элемент любого типа, удалить, перетащить мышью вверх/вниз, дублировать, ряд из нескольких
  элементов; у каждого типа — свои поля: текст с подсветкой MiniMessage и вставкой плейсхолдера из списка, размер,
  выравнивание; предмет — из руки или по id (с автодополнением по hoitems); картинка — выбор файла из списка; шкала;
  кнопка — подпись и **конструктор действий** (список действий, тип из выпадающего списка, поля, порядок, ЛКМ/ПКМ).
- **Живой предпросмотр**: правки видны на голограмме в мире сразу (и в маленьком превью в окне), применяются
  на сервер по кнопке «Сохранить» (или авто), **Отмена/Повтор** (Ctrl+Z / Ctrl+Y) в пределах сессии.
- **Перемещение в мире**: режим «двигать» — голограмма следует за прицелом / стрелки-гизмо по осям (тянуть мышью),
  колёсико — расстояние, Shift — точно, Enter — поставить.
- **Шаблоны**: сохранить голограмму как шаблон, создать из шаблона (несколько готовых: «табличка станции»,
  «меню с кнопками», «информация с шкалой»).
- Редактор только для OP: сервер проверяет каждую правку.

## 4. Протокол
Свой канал клиентского модуля (`ClientModsApi.send(p, "holo", …)`, как у `stations`/`vessels`): полная голограмма при
входе/появлении рядом, дельты при изменении, значения плейсхолдеров отдельно (маленькие пакеты), нажатия и правки
редактора — от мода. Игрок без мода голограмм не видит (опиши; ванильный запасной вариант — не делать).

## 5. Проверка и сдача
- Тесты JUnit: разбор/сохранение json (все типы элементов, страницы), плейсхолдеры (подстановка, частота, только
  изменения), проверка нажатий (расстояние, права, задержка, консольные команды только у OP-голограмм), раскладка
  панели (размеры строк/рядов, не вылезает за ширину), отмена/повтор редактора (если логика вынесена из экрана).
- **Превью PNG без игры** (как у vessels-3/stations): голограмма в теме space с текстом, предметом-заглушкой, шкалой и
  кнопками; экран редактора — в `tasks/holo-1-preview/`. Это главное, по чему примут работу до игры.
- Сборка: `./gradlew build`; `cd client && gradle :core:build :modules:holo:build`.
- Версии: `holo` 0.1.0 (сервер и мод); ядро мода — только если без этого никак (0.84.0, миксины только
  `@Inject`/`@WrapOperation`/`@ModifyReturnValue`/`@Accessor`).
- Отчёт `tasks/holo-1-report.md`: что сделано, что нет (если не успел — что осталось, по пунктам), как выложить, как
