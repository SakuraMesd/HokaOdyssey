# Задача workbench-1: новый блок «Космический верстак» 2×2 блока, высота 1,5, с анимацией

Ветка: `ai/workbench-1` (уже создана от свежего main). Перед работой прочитай CLAUDE.md, DEVELOPER.md, MODULES.md,
CONTENT.md (разделы 2, 7, 10), код `modules/blocks/`, `client/core/.../block/` (PoolBlocks, Remap, CustomBlocks,
BlockSlots) и `client/core/.../model/` (BbModel, BbAnimation, Pose, Models). Отчёт — `tasks/workbench-1-report.md`,
вопросы — `tasks/workbench-1-questions.md`.

**Бюджет ограничен (~$13).** Порядок: сервер (поля, носители, постановка/ломание) → ядро мода (форма блока по shape)
→ анимированная модель блока → тесты. Коммить после каждого шага и сразу обновляй отчёт: если работа оборвётся,
сделанное и отчёт должны остаться. Ядро мода сейчас 0.83.0 → поднять до 0.84.0.

## Что нужно
Именно новый блок, а не сущность: в мире у игрока это блок мода `hoka_odyssey:*` (как остальные свои блоки), ставится
из предмета-блока, ломается как блок, хранится в мире как блок. Сервер (Minestom) новых блоков не знает, поэтому на
сервере он, как и все свои блоки, лежит ванильным носителем из `states.yml`, а мод подменяет его на свой блок (Remap).
Это не меняем — игрок нотный блок не видит. Сущности (INTERACTION, модели на сущностях) и барьеры не использовать.

Сейчас свой блок = 1 клетка + неподвижная модель. Нужно добавить в систему своих блоков две возможности —
**многоклеточный блок** и **анимированную модель блока** — общим способом (через поля config.yml), не только для верстака.

## Размеры (не менять)
- Габарит: 32 × 24 × 32 px = 2 × 1,5 × 2 блока (X × Y × Z), 16 px на блок, как у ванилы. Масштаб 1.
- В файлах сейчас X и Z: −8…24, Y: 0…24 (центр 2×2 в точке 8, 8).
- Блок занимает 4 клетки 2×2 (одна по высоте). Главная клетка — с наименьшими X и Z (до поворота); модель
  привязывается к ней так, чтобы покрыть все 4 клетки: для java_block это X, Z 0…32 относительно главной клетки →
  сдвинуть модель на +8 по X и Z. Для формата free («центр модели в 0» — проверь по CustomBlocks, где именно этот 0 у
  блока) сдвинуть так, чтобы центр модели пришёлся на стык четырёх клеток. Сдвиг делать скриптом по from/to/origin
  элементов и origin групп; ключи анимации не трогать. Проверить тестом габарит после сдвига.
- Хитбокс каждой из 4 клеток: коллизия и рамка выделения 16 × 24 × 16 px (высота 1,5 блока — как у забора, игра
  такое умеет). Верх модели — экран и манипулятор — в пределах этих 1,5 блока.

## Сервер — модуль blocks
Новые поля блока в `module/blocks/config.yml` (имена можно уточнить, но описать в CONTENT.md):
```yaml
space_workbench:
  name: "Космический верстак"
  model: space_workbench.bbmodel      # анимированная (free) — для анимации; поза по умолчанию — для меша
  animation: idle                     # новое: проигрывать анимацию модели в мире
  size: [2, 1, 2]                     # новое: клеток по X, Y, Z
  shape: [0, 0, 0, 16, 24, 16]        # новое: хитбокс одной клетки, px
  rotatable: true
  sounds: { type: metal }
```
- Носители: на каждую часть × поворот — своё место носителя (4 части × 4 поворота = 16 мест типа transparent, запас
  clear = 48 — следить за остатком, писать в лог). `states.yml` только дополнять.
- Постановка: предмет блока → проверить, что все 4 клетки свободны (воздух/заменяемые) и под ними опора, иначе отказ
  с сообщением по-русски; поставить 4 части с поворотом по взгляду игрока. Лицо модели — сторона −Z (ящики,
  манипулятор), экран сзади (+Z); лицо смотрит на игрока.
- Ломание любой части → убрать все 4 части, выпасть одному предмету (в выживании — по правилам mining/survival, если у
  них есть сервис, иначе как обычный свой блок). Взрывы/поршни/вода не должны оставлять «половинку».
- Частям, кроме главной, моду отдаётся пустая модель (они только держат хитбокс). ПКМ по любой части — событие
  «верстак открыт» для главной клетки (окно houi `workbench`: заголовок и кнопка «Закрыть»; логику крафта не придумывать
  — в Minestom нет рецептов, вопрос в questions).

## Мод — ядро (client/core, осознанное изменение, поднять version до 0.84.0)
- Форма блока: блокам запаса (PoolBlocks) отдавать коллизию и рамку из shape своего блока
  (getShape/getCollisionShape по привязанному блоку сервера), по умолчанию — полный куб.
- Анимированная модель блока: если у блока есть animation, главная клетка не кладёт модель в меш чанка, а рисуется
  каждый кадр через конвейер моделей (Models/Pose, как модели сущностей) в позиции блока с поворотом блока; время
  анимации — общее по миру. Ограничить дальность (например, 48 блоков; дальше — поза по умолчанию в меше) и не
  создавать объектов на кадр. Сущности не создавать.
- Миксины только `@Inject`/`@WrapOperation`/`@ModifyReturnValue`/`@Accessor`. Рассчитано на Sodium.

## Тесты (JUnit 5)
- сдвиг модели: габарит после сдвига верный, все элементы в костях, анимация idle найдена;
- 4 клетки и поворот считаются верно для всех 4 сторон; занятая клетка → отказ; ломание части убирает все 4;
- выдача носителей: 16 мест, повторный запуск не меняет уже выданные (states.yml);
- мод: разбор новых полей (size, shape, animation) и форма блока по shape.

## Как проверить в игре (написать в отчёте)

`hoka_odyssey:*`, не нотный; манипулятор двигается, искры вспыхивают, голограмма крутится; на стол можно запрыгнуть

после перезахода верстак на месте. Знак поворота манипулятора: он должен уходить к голограмме — если наоборот, поменять
знаки ключей rotation кости «Манипулятор» в модели. Также — как выложить (модель в module/blocks/…, конфиг, states.yml,
ядро мода, houi-окно).
