# Задача stations-1: космические станции — регионы с видимыми границами и гравитацией станции

Начинаем космические станции. Этап 1 — **регионы станций**: админ выделяет область, игрок **видит её границы**
(красиво, рисует клиентский модуль), внутри региона — **гравитация станции** (обычная, как на земле), снаружи — вакуум
карты. Новый модуль `modules/stations` (сервер) + `client/modules/stations` (мод). Чужие модули tearsmilk
(`items, gravity, gravzones, oxygen, starmap, guns`) **не трогать и не переписывать** — их кода в репозитории нет.

## Как сейчас устроена гравитация (важно)
- Модуль `gravity` (tearsmilk, на сервере `module/gravity.jar`, версия 0.4.0): вакуум/невесомость на картах из его
  конфига (сейчас `cosmos`, `galaxy1`). Модуль `gravzones` (tearsmilk) — свои зоны гравитации топориком.
- У `gravity` есть **публичный сервис для чужих зон** — им и пользуемся. Сигнатуры (сняты `javap` с jar на сервере):
  ```java
  package ink.hoka.odyssey.gravity;
  public interface VacuumService {
      void override(Player p, Mode m);  Mode override(Player p);
      default void force(Player p, boolean b);
      boolean inVacuum(Player p);
      void push(Player p, double x, double y, double z);
      default void recoil(Player p, double x, double y, double z, boolean b);
      default void expectRecoil(Player p, double d);
      void zoneProvider(ZoneProvider provider);        // ← регистрируем свои зоны
      void removeZoneProvider(ZoneProvider provider);  // ← снимаем в onDisable
      static boolean itemInVacuum(boolean b, Mode m);
      enum Mode { MAP, VACUUM, NORMAL }
      interface ZoneLookup { Mode modeAt(double x, double y, double z); }
      interface ZoneProvider { ZoneLookup zones(Instance instance); default void released(ItemEntity item) {} }
  }
  ```
  Смысл (по названиям, проверь по поведению загрузчика модулей): провайдер на карту отдаёт `ZoneLookup`, тот в точке
  говорит `NORMAL` (обычная гравитация), `VACUUM` или `MAP` (как у карты, «не моя зона»). `modeAt` зовётся часто —
  должен быть дешёвым (индекс регионов по карте, без аллокаций).
- Для компиляции: сделай **stub-проект** с этим интерфейсом (тот же пакет, только сигнатуры, `compileOnly`), **не
  класть** его в jar `stations`. В рантайме класс придёт из `gravity.jar` — проверь в `server/.../ModuleClassLoader` и
  `ModuleManager`, как модуль видит классы модуля из `softdepends`/`depends`, и как сервисы ищутся (`services()`), чтобы
  `VacuumService` у нас и у gravity был **один и тот же класс**. `softdepends: [gravity]`: без gravity регионы работают,
  просто без гравитации (в лог одна строка). Переживать `homodule reload gravity` (провайдер перерегистрировать, когда
  gravity снова включён) и `homodule reload stations`.
- Если окажется, что сервис так не получить, — **не лезь** в код gravity; опиши в вопросах и сделай гравитацию в своём
  модуле только для карт, где gravity нет, либо остановись на регионах без гравитации.

## 1. Регионы (сервер, `modules/stations`)
- Регион — коробка (две точки) на карте, имя, название для игроков («Станция Альфа»), владелец (необязательно), флаг
  гравитации (`gravity: normal | vacuum | map`, по умолчанию `normal`). Позже добавятся права/доки — заложи место
  (поле `flags`), но не делай.
- Можно несколько коробок на один регион (станция сложной формы): `/hostation add-box <регион>` из текущего выделения.
- Хранение — `module/stations/regions.json`, атомарная запись, битый файл не перезаписывать.
- Выделение (OP): предмет-указка `/hostation wand` (ЛКМ по блоку — точка 1, ПКМ — точка 2; на кубовых картах блоки
  могут быть не в памяти — только загруженные), или `/hostation pos1|pos2` по месту игрока. Выделение видно игроку
  модом сразу (см. п.2).
- Команды (OP): `create <id> [название]`, `add-box <id>`, `remove <id>`, `rename <id> <название>`, `list [карта]`,
  `info <id>`, `tp <id>`, `expand <id> <блоков> [up|down|all]`, `gravity <id> normal|vacuum|map`, `reload`.
- Пересечение регионов: действует меньший по объёму (как у gravzones), при равном — созданный позже.
- Сервис для других модулей: `StationsApi` — регион в точке, список регионов карты (пригодится докам и кораблям).
- Вход/выход игрока в регион — событие сервиса + сообщение игроку (название станции, плавно).

## 2. Видимые границы (клиентский модуль `client/modules/stations`)
Игрок должен **видеть, где регион**. Сделай красиво, в стиле HUD кораблей (тонкие светлые линии, мягкое свечение):
- Рёбра коробок — тонкие светящиеся линии; грани — едва заметная полупрозрачная «силовая плёнка» с сеткой/шестигранниками,
  которая **проявляется только рядом** (ближе ~8–12 блоков к грани — ярче там, куда подходит игрок, как силовое поле),
  издалека — только рёбра, совсем далеко — ничего. Без мерцания, с плавной анимацией (медленный бегущий блик).
- Внутри региона у края — плёнка видна изнутри так же.
- Цвет по типу гравитации (обычная — голубой, вакуум — янтарный) — в конфиге.
- При входе/выходе — короткая надпись по центру сверху («СТАНЦИЯ АЛЬФА · ГРАВИТАЦИЯ 1g» / «ОТКРЫТЫЙ КОСМОС»), гаснет.
- Режим админа: выделение `wand` видно ярко (жёлтым), регионы — с подписью имени, `/hostation show [id]` включает
  показ всех регионов на 30 с (или переключатель).
- Производительность: десятки регионов на карте, рисовать только ближние; на кубовых картах (cosmos) координаты большие —
  рисовать относительно камеры (без дрожания float). Посмотри, как ядро мода рисует модели/линии, есть ли API для
  мировой отрисовки у модулей (`ClientContext`); если нет — сделай нужный крючок в ядре (ядро → 0.84.0, миксины только
  `@Inject`/`@WrapOperation`/`@ModifyReturnValue`/`@Accessor`).
- Данные регионов сервер шлёт моду своим op (найди свободные номера по CLAUDE.md §5); при изменении — обновление;
  игрок без мода — регионы работают, гравитация работает, только без картинки (в чате — сообщение входа/выхода).

## 3. Гравитация станции
- Внутри региона с `gravity: normal` — обычная гравитация (ходить, прыгать, падать), снаружи — как у карты (вакуум
  `gravity`). Через `VacuumService.zoneProvider` (см. выше). Выброшенные предметы — как решит gravity по `Mode`.
- Переход через границу должен быть плавным для игрока (не телепорт и не рывок) — проверь, что gravity делает при смене
  режима; если резко — опиши в вопросах, не правь gravity.
- Урон от падения: в регионе — как в survival обычно (на вакуумной карте его нет; при входе в регион с высоты — не
  убивать сразу: метка `hoka_fall_safe_until` на 2–3 с, она уже есть в survival).
