# Hoka Odyssey — вводная для агента

Этот файл Claude Code читает сам при старте в корне репозитория. Для других агентов (Codex, Cursor) — скопировать
как `AGENTS.md`. Здесь только общая картина и правила; подробности — в документах, на которые даны ссылки.
Отвечай и пиши комментарии в коде **по-русски**, в стиле существующего кода.

## 1. Что это

**Hoka Odyssey** — Minecraft-сервер про космос: корабли, полёты, астероиды, высадка на планеты.
Две половины, которые работают только вместе:

| Часть | Что | Где |
|---|---|---|
| **Сервер** | **Minestom** (не Paper/Bukkit!) `2026.05.17-1.21.11`, Java 25. Ядро (миры, карты, права, загрузчик модулей) + модули (вся игра) | `server/`, `api/`, `modules/*`, `gen-api/`, `generators/*` |
| **Клиентский мод** | Fabric 1.21.11, обязателен для игроков. Ядро мода + мини-модули, которые сервер присылает на лету (подписаны Ed25519) | `client/core`, `client/modules/*` |

Сервер шлёт моду всё содержимое: блоки, предметы, модели `.bbmodel`, звуки, окна, HUD, небо, клиентские модули.
Ресурс-пака нет, перезаходить для обновления не нужно.

## 2. Где что лежит

```
api/            API для модулей (OdysseyModule, ModuleContext, конфиг, планировщик, сервисы) — compileOnly
server/         ядро → server/build/libs/server.jar
  maps/         карты (maps/<карта>/map.yml), граница, время суток
  tall/         высокий мир и кубические чанки: TallWorld (высота у каждой карты своя), CubeColumn, CubeStore,
                CubeStreamer, CubeLight, HeightIndex, AheadLoad (предзагрузка по курсу)
  gen/          генерация по кубам (ModuleCubeGen), objects/ — вставка объектов, perms/ — операторы
gen-api/        переносимый API генераторов планет (один код и на сервере, и в моде у клиента)
stubs/          заглушки API чужих модулей для компиляции (gravity-api: VacuumService) — в jar не идут
generators/     генераторы: space (космос: астероиды, руды, лут), planet, vale, noise-test
modules/        серверные модули (jar → module/<id>.jar на сервере)
client/core     ядро мода: сеть, кубы, LOD, свет, модели, блоки мода, окна, звук, миксины
client/modules  клиентские мини-модули: sky, planets, ships, vessels, stations, hello (шаблон)
demo-objects/   исходники контента (текстуры, yml карт и блоков, модели)
tasks/          задачи для агентов и их отчёты
```

Серверные модули: `axiom` (редактор Axiom, только OP), `blocks` (свои блоки), `clientmods` (раздача клиентских
модулей, связь сервер↔клиентский модуль), `containers` (сундуки, бочки), `hoitems` (свои предметы, модели в руке),
`hosounds`, `houi` (окна и HUD из JSON), `mining` (ломать только инструментами, лазер Аксиома), `planets`,
`ships` (старые корабли из блоков), `sky`, `stations` (регионы станций: границы, гравитация через сервис `gravity`), `survival` (здоровье, голод, смерть, сохранение игроков), `example` и
`noisegen` (шаблоны).

На боевом сервере есть ещё модули другого разработчика (tearsmilk): `items, gravity, gravzones, oxygen, starmap,
guns`. Их кода в репозитории нет — **не трогать и не переписывать**.

## 4. Главные правила

1. **Это Minestom.** Нет `org.bukkit.*`, `JavaPlugin`, `plugin.yml`, `@EventHandler`. Не выдумывай API —
   проверяй по исходникам Minestom (sources-jar в кэше Gradle).
2. **Новая механика — новый модуль** в `modules/<id>/` (+ `include` в `settings.gradle.kts`). Ядро сервера и
   ядро мода трогать только если без этого никак, отдельным осознанным изменением.
3. В модуле слушатели только через `events()`, команды через `registerCommand()`, задачи через `scheduler()`.
   Всё созданное убрать в `onDisable()`. Модуль должен переживать `homodule reload <id>`.
4. Команды начинаются с `/ho…` (или своё короткое имя модуля). Админ-команды — только OP.
5. Тексты игрокам — по-русски, через Adventure.
6. В тике сервера ничего долгого (файлы, сеть, тяжёлые расчёты) — в `scheduler().async(...)`.
7. Данные игроков и миров не терять: запись в файл атомарная (временный файл → rename), битый файл не
   перезаписывать.
8. Чужие модули — только через сервисы и `depends`/`softdepends`.
9. В git не класть секреты: `signing.key`, токены, пароли, ключи API.
10. **Minecraft на машине агента не запускается.** Проверка в игре — у человека. Всё, что можно, закрывай
    тестами JUnit 5 (`src/test/java`, в `@BeforeAll` — `MinecraftServer.init()`), в конце пиши «как проверить
    в игре».

## 5. Клиентский мод — что важно знать

- Версия ядра мода — `version` в `client/core/build.gradle.kts`. Любая правка ядра — поднять
  версию: сервер раздаёт ядро и по версии решает, обновлять ли игрока (автообновление файлом `.next`).
- Миксины — только `@Inject`, `@WrapOperation`, `@ModifyReturnValue`, `@Accessor` (без `@Overwrite` и `@Redirect`
  там, где можно обойтись).
- Отрисовка мира рассчитана на Sodium (лежит в `client/libs`, в git его нет).
- Сервер↔мод общаются своим каналом с номерами операций (op). Прежде чем занять новый номер — найди
  существующие (`grep` по `op ==` / `case` в `client/core/.../net`, `Models.handle`, `ShipsClient`).
- Модели `.bbmodel`: разбор `model/BbModel`, рисование и `ModelHandle` для модулей — `model/Models`.
  Сейчас понимаются только кубы (меши — задача `tasks/vessels-1.md`).
- Свои блоки — настоящие блоки мода из запаса (`block/PoolBlocks`: solid/clear/pass), сервер хранит их
  ванильными «носителями» (нотный блок, листва, растяжка), мод подменяет номера (`block/Remap`).

## 6. Мир

- Карты — `maps/<карта>/map.yml`. Высокие карты: `tall: true`, `cubes: true`, свои `min_y` и `height`
  (у космоса `cosmos` — −32752…32751, граница 100 000, генератор `space`).
- Генераторы планет — переносимые (`gen-api`): одинаковый результат на сервере и у клиента (`StrictMath`,
  без случайности вне сида). Тесты генераторов сверяют результат с эталоном (`gen-golden`).
- Minestom откидывает игрока назад, если тот влетел в незагруженный столбец: всё, что быстро двигает
  игрока (корабли, полёт), должно грузить столбцы впереди (`tall/AheadLoad`).

## 7. Сборка и тесты

```bash
./gradlew build                         # сервер: ядро + модули + генераторы + тесты
./gradlew :modules:<id>:build           # один модуль
./gradlew :server:test                  # тесты ядра
cd client && gradle :core:build         # ядро мода (wrapper в client/ нет — системный Gradle 9.8, Java 25)
cd client && gradle :modules:<id>:build # клиентский модуль
```

Результат: `server/build/libs/server.jar`, `modules/<id>/build/libs/<id>.jar`,
`client/core/build/libs/hoka-odyssey-<версия>+1.21.11.jar`.

## 8. Инфраструктура (для понимания; агент сам не деплоит)

- Игровой сервер — RU `2.152.87.39`, Pterodactyl, «Hoka Odyssey», порт 25573. Игроки входят через ретранслятор
  `82.147.74.107:25566`. Прочие серверы сети остановлены.
- DE `13.143.134.212` — панель и машина, где работают агенты (пользователь `claude`, без root).
- Выкладку делает администратор: модуль → `module/<id>.jar` + `homodule reload <id>`; ядро сервера и генераторы —
  рестарт; ядро мода → папка `module/clientmods/core/` + `hoclient reload`.
- **Агенту:** ничего не деплоить, не ходить на чужие серверы, не менять системные настройки. Работать в своей
  ветке `ai/<задача>`, коммиты небольшие, сообщения по-русски. Вопросы, которые меняют задачу, — в
  `tasks/<задача>-questions.md`, выбрать самый безопасный вариант и продолжать. В конце —
  `tasks/<задача>-report.md`: что сделано, что нет, как проверить в игре, известные проблемы.
